### 技术结论：Dockview 组件注册时机

本轮尝试让 `DockWorkspace` 直接消费 `panels` 贡献，并动态更新 `components`。

结果：

- Dockview 在初始化后更新 `components` 会抛出：
  `Dockview: Only React.memo(...), React.ForwardRef(...) and functional components are accepted as components`
- 动态更新方案已回退；
- 当前仍由 `DockWorkspace` 显式注册 `board` 面板，插件同时注册同一面板定义；
- 正确方向是：**插件激活完成后再首次挂载 Dockview**，或在插件面板变化时重建 Dockview 实例，而不是运行中替换 `components`。

该结论已记录，避免下一轮重复踩坑。

### 下一阶段

1. 在插件就绪后再挂载 Dockview，从而真正消费 `panels` 贡献；

## 2026-10-31 Phase 27：工作区与面板状态收敛

### 问题

`useWorkspaceStore` 同时保存：

```text
workspaces: WorkspaceView[]
activeWorkspace: WorkspaceView | null
```

同一个 WorkspaceView 有两个可写副本。标题或地图列表更新时，调用方必须同时更新数组和 active 对象，否则会出现大纲标题与当前工作区标题不一致。

Dockview 的活动面板是另一套状态：

```text
活动 map panel
活动 blockdoc panel
activeMapId
selectedNode
```

切换 tab 时，活动面板已经变化，但 activeMapId/selectedNode 可能仍停留在旧文档。

### 实现

工作区：

```text
activeWorkspace 删除
activeRoot: string | null 新增
selectActiveWorkspace(state) 派生当前工作区
setWorkspaces 自动清理失效 activeRoot
```

App 和 WorkspaceBridge 都改用派生 selector。

面板：

```text
DockWorkspace onDidActivePanelChange
  ├─ map panel：同步 activeMapId
  ├─ blockdoc panel：同步 activeMapId + selectedNode
  └─ 默认 map panel：回退到 activeMap 或当前工作区第一张地图
```

`onActiveMap` 回调通过 ref 保持最新，避免 onReady 监听器捕获旧工作区。

### 验证

新增单元测试：

- active workspace 由 activeRoot 派生；
- 工作区标题更新后派生对象同步；
- 移除活动工作区后 activeRoot 清空。

### 补充：文档面板脏状态

原先 `usePanelStore.dirtyPanels` 没有任何写入方，确认放弃修改的对话框实际上不会出现。

现在：

```text
BlockDocumentPanel
  → ImportedPreviewPane panelId={panel.id}

ImportedPreviewPane

  → 面板卸载：清理 false
```
