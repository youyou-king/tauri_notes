# 状态架构契约

## 1. 目标

项目采用编译期模块化单体 + 插件化内核。代码边界已经由 `src/architecture.test.ts` 约束，但状态边界需要单独定义。

本契约解决四类问题：

1. 同一数据存在多个可写副本；
2. UI 通过 `useEffect` 或事件互相“同步”状态；
3. 工具栏、状态栏、装饰层各自解释编辑器状态；
4. 持久化层被误当作第二份真相。

目标数据流：

```text
用户操作
  ↓
Command / Action
  ↓
Canonical State（唯一可写源）
  ↓
Selector / Derived Snapshot（只读投影）
  ↓
UI
```

原则：

- 一个业务状态只能有一个可写源；
- 派生状态不进入 `useState`；
- 事件只用于通知，不用于存储状态；
- localStorage / IndexedDB / SQLite 是持久化适配器，不是运行时真相；
- 局部状态仅用于临时 UI（菜单展开、hover、输入草稿、拖拽预览）。

## 2. 状态所有权

| 状态 | 唯一写入口 | 读取方式 | 持久化 | 投影 |
|---|---|---|---|---|
| 文档内容 | Tiptap transaction | `editorSnapshot` | `.note` 块 | 正文、保存状态 |
| 编辑器选区 | Tiptap EditorState | `selectedBlockAtSelection` | 无 | 工具栏、块布局栏、decoration |
| 工具栏开关 | Tiptap marks/nodes | `EditorToolbarSnapshot` | 无 | H1/H2/B/I/列表状态 |
| 文档统计 | Tiptap doc | `editorSnapshot.stats` | 无 | 状态栏块数/字数 |
| 主题选择 | `ThemeProvider.mode` | `useTheme` | localStorage | DOM data 属性、CSS vars |
| 外观包 | `appearanceRuntime.ts` | runtime selector | IndexedDB runtime record | CSS vars、壁纸、装饰 |
| 当前工作区 | `useWorkspaceStore` | Zustand selector | session | 标题、大纲、导图 |
| 当前节点/文档 | `useWorkspaceSelectionStore` | Zustand selector | session | 大纲/导图/面板 |
| 面板布局 | Dockview adapter | adapter events | layout JSON | 可见性、尺寸 |
| 面板脏标记 | `usePanelStore` | selector | 无 | 保存按钮、关闭确认 |
| 菜单展开 | `useToolbarPopover` | 局部 state | 无 | 按钮 active |
| 搜索高亮索引 | SearchPalette | 局部 state | 无 | 结果行 active |

## 3. 编辑器状态层

### 3.1 唯一来源

编辑器唯一真相是 Tiptap `EditorState`：

```text
doc
selection
storedMarks
```

`ImportedPreviewPane` 不再保存：

```text
selectedBlock useState
stats useState
onSelectionUpdate 手工同步
```

这些数据由 `useEditorSnapshot` 统一派生。

### 3.2 快照结构

```ts
type EditorSnapshot = {
  selectedBlock: SelectedBlock | null;
  stats: { blocks: number; characters: number };
  toolbar: EditorToolbarSnapshot;
};
```

`EditorToolbarSnapshot` 包含：

```text
bold / italic / strike / code
headingLevel
bulletList / taskList / blockquote / codeBlock / tableBlock
link
canUndo / canRedo
```

### 3.3 订阅方式

```text
Editor transaction/selection
  ↓
useEditorSnapshot 的单一订阅
  ↓
setSnapshot(editorSnapshot(editor))
  ↓
所有工具栏/状态栏/布局栏读取同一份快照
```

组件禁止：

- 用 `useState` 镜像 `selectedBlock`；
- 在多个组件内分别调用 `editor.isActive(...)`；
- 在 `onSelectionUpdate` 中复制编辑器状态。

### 3.4 规则

```text
H1 → toolbar.headingLevel === 1
H2 → toolbar.headingLevel === 2
段落 → toolbar.headingLevel === 0
撤销 → toolbar.canUndo
重做 → toolbar.canRedo
```

## 4. 主题运行态（已完成）

主题模式仍由 `ThemeProvider` 管理；外观包由 `appearanceRuntime` 管理，二者通过 `resolved` 单向同步。

运行时结构：

```ts
type ThemeRuntime = {
  selection: ThemeSelection;
  systemDark: boolean;
  resolved: "dark" | "light";
  appliedPack: {
    id: string;
    variant: "dark" | "light";
    colors: Record<string, string>;
    surfaces: Record<string, unknown>;
  } | null;
};
```

优先级：

```text
appliedPack.variant
  > custom theme
  > system / dark / light
```

实现位置：

```text
src/plugins/theme/appearanceRuntime.ts
```

持久化记录：

```text
StoredAppearanceRuntime {
  pack: AppearancePackManifest
  assets: {
    dark:  { wallpaper, decorations }
    light: { wallpaper, decorations }
  }
}
```

保存在 IndexedDB `runtime:v1`。切换深浅色、刷新页面后都会从同一份记录重新激活对应 variant。

`appearanceApplier` 退化为低层 DOM 适配器，只负责写 CSS 变量、回滚和派发 `appearance:applied`；不再作为外观包真相。

## 5. 工作区/面板状态（已完成第一阶段）

- `useWorkspaceStore.workspaces`：工作区唯一列表；
- `useWorkspaceStore.activeRoot`：只保存当前工作区 root；
- `selectActiveWorkspace`：从 `workspaces + activeRoot` 派生当前工作区；
- `useWorkspaceSelectionStore`：当前节点、当前导图；
- Dockview：布局真相；
- `usePanelStore`：脏标记真相；
- Dockview 活动面板变化会同步 `activeMapId/selectedNode`；
- 文档编辑器的未保存状态通过 `panelId` 上报到 `usePanelStore`；
- 保存成功、加载完成或面板卸载时清理 dirty；
- UI 组件只读 selector，不复制 selected 节点。

`activeWorkspace` 不再作为独立可写字段存在，避免标题、地图列表更新后留下旧对象。

## 7. 判断标准

一个状态改造是否合格：

- 是否存在唯一可写源；
- 刷新/恢复后是否与持久化一致；
- 是否可以从来源纯函数计算出所有投影；
- 是否存在两个组件各自保存同一业务状态；
- 是否存在“关闭一个再打开另一个”的临时同步代码。
