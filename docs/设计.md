# 设计文档：导图式 Markdown 知识库

> 最后核对：2026-10-31 | 当前版本 v0.1.1 | 基线 133 / 38 / 33

> **状态（2026-10-28）**：产品蓝图。Bevy 原型已冻结并删除。
>
> **当前主线**：Tauri 2 + React 19 + **Tiptap/ProseMirror 全块编辑器** +
> SQLite `.note` 单文件；详细架构见 [全块编辑器架构](全块编辑器架构.md)。
>
> **已定路线**：
> 1. 单 Tiptap 编辑器覆盖所有文档大小，块是文档节点；
> 2. SQLite 是内容真相，Markdown 只作为导入/导出语法；
> 3. `.note` 单文件保存，支持备份和 WAL；
> 4. 标题改名迁移正文，删除标题必须确认，不静默删子文档；
> 5. 标签页/停靠用 **dockview**，不自研 Flex 停靠；
> 6. 导图画布用 **React Flow**。
>
> 详细架构与验收见 [设计文档索引](README.md) 和 [全块编辑器架构](全块编辑器架构.md)，界面细节见 `界面设计.md`。

## 1. 产品定位

以思维导图为组织方式的知识库。导图是主结构，节点是 Markdown 文档的容器。**结构从内容中自动生长**：写 `#` 标题，导图上长出子节点。

节点文档内部支持**块级自由布局**：默认流式写作，可切换画布视图自由拖动缩放块，用构图表达关系。

## 2. 数据模型

```
.note 知识库（SQLite 单文件）
└── 多张独立导图
    └── 树结构
        └── 节点（标题 + 一篇 Markdown 文档 + 子节点列表）
            └── 文档内的块（内容 + 可选布局信息）
```

- 一个 `.note` 文件 = 一个知识库，内含多张导图和文档。
- 每张导图是一棵独立的树。
- 每个节点挂一篇完整 Markdown 文档。
- **节点文档里的 `#` 标题，自动映射为该节点的子节点**；正文段落不生成节点。
- **文档内的块可携带可选布局信息**，默认流式排列，画布视图下按布局摆放。

树结构与文档内容不是两套数据，而是同一份内容的两种呈现。

## 3. 自动建树

**规则**：文档编辑结束后解析标题，有对应子节点则跳过，没有则创建。系统只回答一个问题：当前文档里的标题，树上有没有对应节点？

**边界处理**：

| 情况              | 处理                             |
| ----------------- | -------------------------------- |
| 跳级标题          | 就近挂载到最近的更高级标题下     |
| 文档开头就是 `##` | 视为根节点的直接子节点           |
| 标题改名          | 保留原节点 ID 和文档正文，只更新标题与树节点标题；重名时需确认合并/改名 |
| 删除标题行        | 先确认；确认后把节点和文档移到 `.trash/`，不做不可恢复的硬删除 |
| 删除标题后又撤销  | 从 `.trash/` 恢复节点与文档       |

**数据安全原则**：自动建树可以“自动长出新节点”，但不能因为改一个标题就静默丢掉一篇文档。
改名是迁移，不是删除重建；删除必须由用户确认，并且有回收站/备份。

## 4. 分层写作

父文档写概括，子文档写细节。

父文档每个标题旁有**详情按钮**：点击后导图聚焦对应子节点，打开子节点的文档标签页，面包屑可返回。

辅助理解：
- 空子节点用虚线/浅色标记。
- 父文档某标题下正文过长时，提示“是否移到子文档”。
- 节点不显示正文摘要，用样式区分状态（见 §6）。

## 5. 节点移动与结构迁移

**默认拖动节点只移动画布位置**，不改变树结构；位置写入 `layout.json`，节点进入手动布局。

**重挂父节点是显式操作**：右键菜单选择“移动到…”，或拖到节点内部热区并在确认提示后执行。
只有重挂父节点才迁移文档内容：

1. 从原父文档摘出该节点对应的标题段落（标题行到下一个同级/更高级标题前）。
2. 从原父文档删除该段。
3. 插入新父文档；若已有完全相同标题，则正文**追加**到该标题下，不重复插入。
4. 更新树结构：从原父 `children` 移除，加入新父 `children`。
5. 节点自身文档和子树原封不动，随节点迁移。

**细节**：标题层级保持原样；合并时已有内容在前、拖入内容在后；支持撤销。
默认拖动和重挂分开，避免“想挪一下位置，结果正文搬家”的误操作。

## 6. 节点表现样式

节点是结构单元，不显示正文摘要。用视觉区分状态：

| 状态       | 样式                               |
| ---------- | ---------------------------------- |
| 空节点     | 虚线边框、降低不透明度、次级文字色 |
| 有内容节点 | 实线边框、正常不透明度、主文字色   |
| 正在编辑   | 左侧色条或外发光                   |
| 手动布局   | 角落小圆点标记                     |

摘要会膨胀节点尺寸、增加噪音；样式传达信息更省空间。

## 7. 视图与交互

界面按 `界面设计.md`：

- **顶部工具栏**：工程名、保存、主题、窗口布局、搜索；
- **左侧导航**：导图列表 + 最近文档；`Ctrl+B` 折叠；节点树不再放左栏；
- **标签页**：导图标签页和文档标签页平权；单击预览、双击固定；
- **自由布局**：dockview；一个 Leaf = 一个 Pane，
  Pane 内多 Tab 但只显示 active，多个 Pane 同时显示不同内容；
  拖 Tab 到标签栏合并，拖到 Pane 边缘新建 Split；
- **导图标签页**：无限画布、树形布局、节点位置拖动、视口持久化；
- **文档标签页**：面包屑 + 块级即时渲染编辑器，滚动位置持久化。

导图节点只显示标题，完整内容在文档标签页查看。

## 8. 块级自由布局（编辑面板内部）

### 8.1 定位

编辑面板内部是**两层结构**：节点文档由若干 Markdown 块组成，块与块之间默认流式排列，但允许切换到画布视图自由构图。

这一层与导图层的节点拖动是**不同层级**的操作：

|          | 节点级拖动（§5）         | 块级拖动（本节）                 |
| -------- | ------------------------ | -------------------------------- |
| 操作对象 | 导图上的树节点           | 编辑面板内的 Markdown 块         |
| 影响     | 改变树结构，迁移文档内容 | 改变块在文档内的位置，不改树结构 |
| 数据     | 文档内容 + 树结构        | 文档内容 + 块布局信息            |

### 8.2 数据模型：内容与布局解耦

每个块分离为内容与可选布局：

```rust
struct DocumentBlock {
    content: String,              // Markdown 源码，唯一真相
    layout: Option<BlockLayout>,  // None = 走流式默认排列
}

struct BlockLayout {
    position: Option<Vec2>,       // 相对父容器的位置，M4 原型后确定语义
    size: Option<Vec2>,           // None = 由内容撑开
    group: Option<GroupId>,       // 组内流式、组间自由
}
```

**布局表示**：当前采用 12 列行式网格，用户控制块跨度和高度，布局器计算位置；
块级自由画布仍是未来方向，但不作为当前主架构。

### 8.3 双视图：流式与画布共享同一份数据

- **流式视图（默认）**：忽略 `layout`，块按列表顺序流式排列。即 Typora 式写作体验，零额外操作。
- **画布视图**：读取 `layout`，有布局的块按相对位置摆放；没有布局的块自动排列在画布空白区域。画布支持平移缩放。

**视图切换只决定“是否读取 layout、用哪个父容器”**，不是两套布局系统；切换时块实体不销毁。
从画布切回流式时 `layout` 保留但不生效，下次切回恢复构图。

M4 原型的验收：拖动 5 个块、缩放 1 个块、切换流式/画布、重启后布局还在；达不到就不全量采用。

### 8.4 组容器：两级结构

一组块可以放入 `BlockGroup`，**组内流式、组间自由**。

- 用户把“三个相关段落”打包成组，在画布上拖动整个组。
- 组内文字仍然自动换行、自动排列，写作体验不变。
- 组间可自由摆放，表达块与块之间的关系。

### 8.5 布局模板

提供“左右对比”“中心辐射”“时间线”等预设。用户选中几个块，点模板，系统**自动写入相对位置/分组**，不需要手动拖每个块。模板生成后仍可微调。模板只生成布局数据，不改变 Markdown 内容。

### 8.6 交互分离：拖动、缩放、编辑互不误触

画布视图下，块的三种操作通过**独立响应区域物理分离**：

| 操作 | 响应区域               | 机制                                |
| ---- | ---------------------- | ----------------------------------- |
| 拖动 | 块的整体背景或标题栏   | 拖拽状态机，带阈值区分点击与拖动    |
| 缩放 | 块的边缘或角部专用手柄 | 手柄是独立实体，有独立 picking 区域 |
| 编辑 | 块的正文区域           | 点击进入 Typora 式块级编辑态        |

用户不需要靠“移动距离猜意图”，三种操作各有各的物理区域。

### 8.7 与块级编辑的融合

画布视图下，块的内部仍然是 Typora 式编辑：点击正文进入编辑态，光标所在块显示源码，离开后渲染。**构图和写作在两个层级上**——容器位置是构图，容器内容是写作，互不干扰。

## 9. 文件结构

`.note` 是单个 SQLite 文件，启用 WAL。

```text
my-notes.note
├── maps                 导图列表
├── map_nodes            导图节点与树结构
├── documents            文档元数据
├── blocks               块元数据与 content_json
├── block_references     块引用 / 视口
├── boards               对照板
├── assets               图片等资源
└── 其他索引表           搜索、顺序、版本
```

写入规则：

- SQLite 事务保证一次保存的原子性；
- 使用 WAL，异常退出后可恢复；
- 备份通过 SQLite backup 或导出文件完成；
- 删除节点/文档前需要确认，并处理关联引用；
- 图片资源存入资源表，不依赖外部目录；
- `.note` 可整体复制、备份和迁移。

文档可导出为 Markdown；知识库本身不再依赖 `meta.json`、`maps.json` 等散落文件。

## 10. 设计原则

- **单一真相**：节点文档是内容真相，标题决定树结构；块内容是文档真相，布局是可选附加层。
- **不静默丢内容**：标题改名迁移正文；删除标题/节点必须确认并进回收站；所有结构操作可撤销。
- **先验证后定型**：布局/主题/画布都先做最小原型；新主线的停靠用 dockview、主题用 CSS 变量。
- **编辑器先可用**：保存、撤销、精确光标先于导图和画布。
- **导图与文档平权**：两者都是标签页，没有固定主视图；左侧只负责“打开什么”。
- **预览与固定分离**：单击预览、双击固定，避免浏览时标签页膨胀。
- **拖动与重挂分离**：拖动默认只移动位置；重挂父节点必须走显式菜单/确认。
- **规则可预测**：自动建树只回答“标题有无对应节点”，节点拖动只做“内容搬家 + 树更新”。
- **分层写作**：父概括、子细节；节点内默认流式、可选构图。
- **状态用样式表达**：节点不堆文字，用边框、透明度、标记区分。
- **交互物理分离**：拖动、缩放、编辑各有独立响应区域，不靠阈值猜意图。
- **用户最终控制**：系统保证一致性，合并、删改、布局由用户手动决定。
