# 书库身份模型

> 状态：已完成。  
> 日期：2026-11-04。  
> 目标：身份只用 `LibraryId`，路径只作为文件位置。

## 1. 结论

- 书库身份保存在书库文件内部，不依赖 `libraries.json`；
- registry 只是索引，负责 `LibraryId ↔ 当前路径 / 标题`；
- `WorkspaceView.id` 是前端唯一身份；
- 路径只用于打开、导入、导出、备份、资产和底层文件 I/O。

## 2. 数据格式

### `.notes` 目录

`meta.json`：

```json
{
  "schema_version": 1,
  "id": "lib_...",
  "title": "书库标题"
}
```

### `.note` 文件

SQLite `library_meta` 表：

```text
id, title, created_at
```

由当前 schema 创建。旧 `.note` 首次打开时补写 ID 和标题元数据。

### registry

应用数据目录的 `libraries.json`：

```text
version: 3
libraries: {
  "lib_...": { id, path, title }
}
```

- registry v3 只保存 `id/path/title`；
- 旧版本直接冷启动，不做迁移；
- 写入使用 `.libraries.json.lock` 跨进程锁，并在锁内完成 `load → mutate → save`。

## 3. 命令边界

前端只使用：

```text
register_library(path)  -> WorkspaceView
open_library(id)        -> WorkspaceView
rename_library(id,title)-> WorkspaceView
relocate_library(id,path)-> WorkspaceView
forget_library(id)
```

后端 [library_resolver](../src-tauri/src/library_resolver.rs) 负责唯一的：

```text
LibraryId -> current LibraryPath
```

以下服务只接收 `LibraryId`：

- Board
- ImportedDocument
- Map
- Reference
- Search
- Storage close / verify / backup
- Bootstrap / import / database status

以下位置仍使用真实路径：

- 打开/新建文件时的选择器；
- 导入来源、导出目标；
- 图片/附件源文件；
- 备份目标；
- SQLite 实际文件路径；
- 编辑器需要的 `workspaceRoot`。

## 4. 复制、移动、导入

- 同一 ID 且旧路径不存在：视为移动，保留 ID；
- 同一 ID 且旧路径仍存在：视为副本，给副本写入新 ID；
- 导入外部书库：保留原 ID；
- 导入同名副本：冲突时生成新 ID；
- 移动/重定位后关闭旧路径的 SQLite 连接池。

## 5. 前端状态

- `WorkspaceView.id`：稳定身份；
- `WorkspaceView.root`：当前位置；
- `workspaceStore.activeId`：当前书库；
- Dockview 面板参数、活动导图、工作区激活/卸载/重命名：`LibraryId`；
- 会话 v4：`libraries`、`activeId`、`missing`；
- 缺失书库持久化到会话，启动时可重新定位或移除；
- 标题只来自后端 metadata/registry，前端不保存标题副本；
- `LibraryId` 类型为 `lib_` 前缀，后端 `parse` 同步校验；
- `LibraryPath` 使用 brand 类型，普通字符串不能直接传入文件位置 API。

## 7. 只读书库策略

只读 `.note` 和只读 `.notes` 目录都**不支持直接打开**。

- 可写性由真实存储操作确认：`.note` 用 SQLite 写事务，`.notes` 用 `meta.json` 写入；
- 不可写时返回明确错误：

```text
该 .note 文件为只读，当前版本不支持直接打开。请复制到可写目录后重试。
该 .notes 目录为只读，当前版本不支持直接打开。请复制到可写目录后重试。
```

- 不做只读模式、不生成临时 ID、不打开 read-only SQLite；
- 帮助库等内置资源由上层复制到缓存后再打开。

## 8. 明确不在范围

- 数据库连接池和搜索缓存仍按路径，作为内部位置缓存；
- registry 与旧版本 registry 的迁移。
