# 系统架构审计

> 审计日期：2026-11-01  
> 范围：数据访问、持久化、前后端契约、运行时状态、移动端目标与构建  
> 关联：[输入与移动端架构审计](输入与移动端架构审计.md)、[平台抽象与移动端重构方案](平台抽象与移动端重构方案.md)、[ADR-007](adr/ADR-007-config-format-boundaries.md)

## 1. 结论

输入层之外，项目还有四类系统级问题：

1. **移动端目前是响应式壳，不是已验证的移动端目标**；平台抽象方案已定义，原生工程尚未初始化；
2. **数据库访问按命令打开连接并重复检查迁移**；
3. **bundle identifier 切换后没有旧数据迁移**；
4. **配置、状态、契约和备份没有统一的序列化边界**。

这些问题的共同点是：它们不是 UI 细节，而是会影响数据安全、启动延迟、后续多端一致性和可测试性的底座。

## 2. 优先级

| 优先级 | 问题 | 影响 |
|---|---|---|
| P0 | 移动端没有真实目标与设备验证 | 无法证明触控、安全区、软键盘和返回行为一致；平台抽象方案已定义 |
| P0 | 每个数据库命令重新打开连接并检查迁移 | 延迟、锁竞争、移动端频繁操作放大 |
| P0 | identifier 切换无数据迁移 | 升级用户的设置、主题、会话可能丢失 |
| P1 | 持久化碎片化，备份只覆盖 `.note` | 换机/重装无法恢复工作环境 |
| P1 | TS/Rust 契约手写，错误码单一 | 参数漂移，错误无法分类处理 |
| P1 | 编辑器快照按订阅字段重复全量计算 | 大文档事务开销成倍增加 |
| P1 | `shellActions` 单向事件无返回结果 | 调用方无法统一处理失败 |
| P2 | 命令/仓储重复入口、疑似死命令 | 行为分叉，维护成本上升 |

## 3. P0：移动端不是“移动端产品”

当前存在：

- `MobileShell` 响应式布局；
- 600px viewport 的 E2E；
- 触控按钮和底部 tabbar。

当前不存在：

- Android/iOS Tauri 工程；
- `src-tauri/gen/android` 或 `ios`；
- 真机/模拟器 CI；
- safe-area、软键盘 inset、触控手势验收；
- 系统返回键/导航栈验证。

因此只能证明：

> 桌面 WebView 缩到 600px 时，移动布局能显示。

不能证明：

> Android/iOS 用户的真实体验与桌面一致。

> 2026-11-01 方案：平台抽象与移动端重构方案已定义，明确使用 Runtime 组合根、Shell 组合和平台端口；当前仍未初始化 Android/iOS 工程。本文保留“先决策、再实施”的顺序，具体任务见 [平台抽象与移动端重构方案](平台抽象与移动端重构方案.md)。

**建议**

先做产品决策：

- 若只做桌面小窗口：把 `MobileShell` 改名为 compact layout，不再承诺移动端；
- 若真做移动端：补 Tauri mobile target、设备矩阵、safe-area、软键盘、返回键和触控 E2E，再谈“体验一致”。

## 4. P0：数据库按命令打开并检查迁移

> 2026-11-01 已落地：每个 workspace 使用 `SqlitePool`（最多 4 个连接），迁移只在进程内首次打开时执行；卸载 workspace 时通过 `close_workspace_database` 关闭连接池并清理初始化状态。测试会显式回收池，避免临时目录被锁。

文档、导图和工作区命令基本都通过：

```rust
database::open_for_import(&workspace)
```

该函数内部：

```rust
let _guard = DATABASE_INIT_LOCK.lock().await;
let mut connection = sqlite::connect(&path).await?;
migrate(&mut connection, &path).await?;
```

问题是：

- 每次 IPC 都新建连接；
- 每次都要检查 schema 迁移；
- 所有工作区初始化经过一个全局异步锁；
- 读操作也被初始化路径串行化；
- 移动端频繁切换文档、搜索、自动保存时延迟会叠加。

**建议**

引入应用级数据库会话：

```text
AppState
  └─ DbManager
       ├─ workspace -> SqlitePool
       ├─ schema_version
       └─ migrate_once()
```

迁移只在打开工作区时执行一次；之后命令复用连接池。这样也能支持后台索引、批量保存和并发读。

## 5. P0：identifier 切换没有数据迁移

当前 identifier：

```text
com.youyou.tauri-notes
```

此前使用过：

```text
com.example.tauri-notes
```

Tauri 的 app data、WebView 用户数据和 localStorage 路径通常与 identifier 绑定。当前仓库未看到旧路径迁移逻辑。

可能结果：

- `.note` 文件还在；
- 会话、主题、自定义设置、插件偏好丢失；
- 用户认为“软件坏了”。

**建议**

二选一：

1. 未有真实用户：明确记录“不迁移”，保持新 identifier；
2. 已有用户：首次启动迁移旧 app data 和 WebView 数据，并写入迁移标记。

## 6. P1：持久化碎片化，备份不完整

> 远程笔记/多端同步尚未纳入本审计，列为待讨论；约束见 [平台抽象与移动端重构方案](平台抽象与移动端重构方案.md) 第 19 节。

设置和状态分散在：

```text
localStorage
  ├─ session
  ├─ dock layout
  ├─ workspace title
  ├─ theme
  ├─ plugin preferences
  └─ last directory

IndexedDB
  └─ appearance assets
```

而备份命令主要覆盖 `.note` 数据库，不包含：

- dock 布局；
- 主题和外观资源；
- 插件偏好；
- 窗口/工作区偏好；
- 未来的 keymap。

用户复制 `.note` 只能恢复内容，不能恢复工作环境。

**建议**

建立统一 `AppSettings`：

```ts
type AppSettings = {
  version: number;
  session: SessionSnapshot;
  layout: DockLayout;
  theme: ThemePreferences;
  keymap: KeymapProfile;
  plugins: PluginPreferences;
};
```

提供整体导出/导入，备份包至少包含：

```text
notes.note
app-state.json       # 会话/布局等机器快照
keymap.toml          # 人类可编辑配置
themes/
```

格式边界见 [ADR-007](adr/ADR-007-config-format-boundaries.md)：配置文件用 TOML，运行时状态用 JSON，内容用 SQLite。

## 7. P1：前后端契约手写，错误码单一

前端调用：

```ts
command("list_imported_documents", { workspace })
```

后端：

```rust
#[tauri::command]
async fn list_imported_documents(workspace: String) -> Result<..., CommandError>
```

参数、返回类型和错误结构依赖人工同步。

Rust 侧错误主要是一个：

```rust
CommandError { code: "COMMAND_FAILED", message }
```

问题：

- 参数改名后运行时才暴露；
- 前端无法区分文件不存在、权限不足、数据库损坏、校验失败；
- 移动端/桌面端只能显示同一段 message；
- 无法可靠生成客户端 SDK。

**建议**

- 用 `ts-rs`、`specta` 或 JSON Schema 生成 TS 类型；
- 错误改为枚举：

```rust
enum CommandErrorCode {
  NotFound,
  PermissionDenied,
  DatabaseCorrupted,
  ValidationFailed,
  Conflict,
}
```

前端按 code 决定提示、重试和恢复，而不是匹配 message。

## 8. P1：编辑器快照重复全量计算

> 2026-11-01 进展：`editorSnapshot` 已按 ProseMirror `EditorState` 缓存，同一 transaction 的多个字段订阅复用一次计算。

`useEditorField` 每个字段订阅都会执行：

```ts
editorSnapshot(editor)
```

`editorSnapshot` 每次计算：

- 当前选中块；
- 整个文档的 `textContent.length`；
- 工具栏全部状态。

如果同时有 `selectedBlock`、`toolbar`、`stats` 三个订阅，一次 transaction 会计算三次完整快照。

**建议**

- 每个 transaction 只计算一次 snapshot；
- 用共享 store 分发字段；
- 把 `stats` 做成惰性/节流计算，不要每次光标移动都扫全文。

## 9. P1：`shellActions` 是单向事件

```ts
shellActions.openSettings(): void
```

只 `emitAppEvent`，没有返回值、Promise 或错误通道。

问题：

- 调用方不知道是否成功；
- 移动端/桌面端无法统一处理失败；
- 迁移到 Action 层后仍是“发完就不管”。

**建议**

改为有结果的端口：

```ts
type ShellPort = {
  openSettings(): Promise<Result<void>>;
  openHelp(): Promise<Result<void>>;
  openSearch(): Promise<Result<void>>;
};
```

事件总线保留做通知，不作为命令执行主通道。

## 10. P2：其他结构性问题

### 命令与仓储重复入口

- `documentService.list` 走 `command`；
- `TauriImportedDocumentRepository.list` 直接 `invoke`。

两条路径的校验、错误和测试容易分叉。建议统一为：

```text
UI -> Application Service -> Repository Port -> Tauri Adapter
```

### 疑似死命令

`index_blocks_db` 后端仍注册，但前端没有调用点。建议做一次 IPC 使用率扫描，删除未使用命令。

### 标题双写

`documents.title` 与 `map_nodes.title` 同时存在，多个重命名路径需要事务同步。建议把重命名收敛到一个 `rename_document` 用例，避免分散同步。

### App 编排偏重

`App.tsx` 约 348 行，同时负责 workspace、session、panel、command、lifecycle 和 plugin readiness。建议在 Action Registry 落地时，把输入/命令/面板协调移出 App。

## 11. 建议顺序

1. 明确移动端目标：真移动端，还是 compact desktop；方案见 [平台抽象与移动端重构方案](平台抽象与移动端重构方案.md)；
2. 数据库会话化：连接池 + 迁移一次；**已完成**；
3. identifier 迁移决策；
4. Action Registry + Input Router；
5. 统一持久化与备份；
6. Rust ↔ TS 契约生成；
7. 编辑器快照优化。

其中 2、3 是底座，4 是输入解耦核心，1 决定移动端投入是否值得。
