# 跨文档视口方案（讨论稿）

> 最后核对：2026-10-31 | 当前版本 v0.1.1 | 基线 133 / 38 / 33

> 状态：引用/对照板已实施，完整讨论保留。
> 2026-10-28 架构更新：内容真相是 SQLite `.note` 块模型；视口 = 块引用、
> 对照板等交互仍有效，但“Markdown 是内容真相 / 整篇 CodeMirror”前提已由
> [全块编辑器架构](全块编辑器架构.md) 替代。
> 定位：研究型知识库、技术笔记、学习资料。
> 原则：视口只保存引用和视图状态。

---

## 1. 结论先行

视口不做成“复制一段内容放进窗口”，而是：

> **视口 = 对某个 Markdown 块的实时引用。**

- 源内容仍在原文档；
- 视口显示源块的最新内容；
- 同一源块可被多个视口引用；
- 视口只读，点击可跳到源文档；
- 视口尺寸、缩放、排列属于视图状态，不写进正文。

---

## 2. 为什么需要跨文档引用

研究型知识库的真实场景：

- 论文 A 的结论固定在论文 B 的笔记旁边；
- 技术文档的代码片段固定到项目笔记；
- 多个来源的同一概念并排对照；
- 学习资料把原文和解释放在一起。

如果视口保存内容副本，会出现：

- 源内容更新，视口不更新；
- 搜索找不到副本；
- 导出不知道以哪份为准；
- 同一段内容出现多个版本。

因此必须保存引用。

## 3. 核心对象

### 3.1 文档 ID

```text
docId = mapId/nodeId
```

- 节点改名不变；
- 文档移动不改 docId；
- 跨导图也能定位。

### 3.2 块 ID

Markdown 本身没有块 ID。

被引用的块写入隐藏 HTML 注释：

```markdown
<!-- notes:block=block_a1b2 -->
这一段内容被其他笔记引用。
```

- 合法 Markdown；
- 渲染不可见；
- 块移动时 ID 跟着走；
- 只在第一次被引用时写入；
- 导出普通 Markdown 时可以移除。

### 3.3 引用记录

```json
{
  "blockId": "block_a1b2",
  "lastDocId": "map_001/node_002",
  "lastTitle": "论文 A / 方法",
  "fingerprint": "内容指纹"
}
```

- `blockId`：主身份；
- `lastDocId / lastTitle / fingerprint`：失效提示和重新关联的辅助信息。

## 4. 宿主模型：先做对照板

### 4.1 推荐：视口属于“对照板”，不直接嵌入普通 Markdown 正文

原因：

- 普通文档是线性 Markdown；
- 视口是二维布局；
- 如果两者混在一起，阅读顺序、导出顺序、拖拽顺序会打架。

对照板是一个独立视图：

```text
普通文档：连续 Markdown 编辑
对照板：引用卡片 + 打包布局
```

用户从任意文档选中块，执行：

> 固定到对照板

生成一张引用卡片。

### 4.2 普通文档正文暂不内嵌视口

“在正文里直接出现窗口”放到后续阶段。

第一版只做对照板，避免把 Markdown 顺序和视觉顺序混在一起。

---

## 5. 对照板文件

```text
workspace/
├─ maps.json
├─ map_001/
│  ├─ tree.json
│  └─ docs/
└─ boards/
   ├─ board_001.json
   └─ board_002.json
```

示例：

```json
{
  "version": 1,
  "title": "论文对照：虚拟列表",
  "items": [
    {
      "id": "vp_01",
      "blockId": "block_a1b2",
      "lastDocId": "map_001/node_002",
      "lastTitle": "论文 A / 方法",
      "width": 460,
      "height": 240,
      "zoom": 1,
      "collapsed": false
    },
    {
      "id": "vp_02",
      "blockId": "block_c3d4",
      "lastDocId": "map_001/node_007",
      "lastTitle": "论文 B / 结论",
      "width": 460,
      "height": 240,
      "zoom": 1,
      "collapsed": false
    }
  ]
}
```

不保存：

- 源正文；
- 渲染 HTML；
- 绝对 x/y；
- Markdown 副本。

## 6. 布局

### 6.1 列式打包，不做自由坐标

```text
按 items 顺序
→ 放入当前最短的列
→ 允许跨列
→ 自动补位
→ 永不重叠
```

- 删除卡片：下面补上；
- 拖入卡片：后面的让位；
- 调整大小：松手后重新打包；
- 拖动只改变 items 顺序，不保存 x/y。

### 6.2 卡片尺寸

```text
最小宽度 320px
默认宽度 460px
最小高度 180px
默认高度 min(内容高度, 360px)
最大高度 70vh
```

### 6.3 内部排版

```text
宽度 → 换行
高度 → 可见区域
缩放 → 字号
滚动 → 放不下时出现
```

- 宽度变化：重新换行，字号不变；
- 高度变化：只改可见行数，不重排；
- 缩放：75% / 100% / 125% / 150%；
- 最低字号 13px；
- 正文纵向滚动；
- 代码/表格横向滚动；
- 窄卡片减小内边距、标题降一档；
- 宽卡片正文最大约 `68ch`。

## 7. 交互

### 创建

1. 在任意文档选中内容；
2. 自动吸附为完整 Markdown 块；
3. 右键/浮动按钮“固定到对照板”；
4. 选择已有板或新建板；
5. 源文档不变。

### 卡片

```text
┌────────────────────────────────┐
│ 论文 A / 2.3 方法          ↗   │
├────────────────────────────────┤
│ 大文档如果整篇挂载 DOM……        │
│ 输入和滚动都会被节点数拖慢。     │
│                          ▐     │
└────────────────────────────────┘
```

- 标题：来源标题；
- `↗`：打开源文档并跳到该块；
- 卡片只读；
- 双击可临时放大阅读；
- 编辑在源文档完成，不在卡片里塞编辑器。

### 调整

- 拖标题栏：改变顺序；
- 拖边框：调整宽高；
- 缩放按钮：调整字号；
- 折叠：只保留标题；
- 删除卡片：只删引用，不删源内容；
- 撤销：一次拖拽/调整作为一次操作。

## 8. 引用生命周期

| 情况 | 行为 |
|---|---|
| 源块正文修改 | 视口自动更新 |
| 源文档改名/移动 | docId 不变，继续解析 |
| 源块移动到其他文档 | blockId 跟随，全局索引重新定位 |
| 源块复制 | 复制件生成新 blockId，旧引用仍指向原块 |
| 源块删除 | 卡片显示“来源已失效”，可重新关联 |
| 源文档删除 | 同上 |
| blockId 丢失 | 用 fingerprint 尝试恢复 |
| 两个块重复 ID | 视为冲突，提示用户选择 |

## 9. 架构分层

```text
domain/
  Workspace
  Document
  Block
  BlockId
  Reference
  Board
  Layout

application/
  ResolveReference
  CreateBoardItem
  ReorderBoardItem
  ResizeBoardItem
  SetBoardZoom
  WatchSource

infrastructure/
  WorkspaceIndex
  BlockAnchorStore
  BoardStore
  TauriDocumentStore

ui/
  BoardView
  BoardCard
  SourcePicker
  DocumentPane
```

规则：

- `domain` 不依赖 React / 编辑器 / Tauri；
- `application` 只做用例编排；
- `infrastructure` 负责索引、文件、Rust IPC；
- `ui` 不直接解析 Markdown；
- 卡片不内嵌第二套编辑器；
- 引用只依赖 blockId，不依赖文件路径。

## 13. 推荐 MVP

先做最小闭环：

1. 选中一个块；
2. 固定到新建对照板；
3. 显示只读卡片；
4. 调整宽度、缩放、滚动；
5. 点击回到源文档；
6. 源块修改后卡片更新；
7. 保存/重开 board。

这七步跑通，再考虑内嵌正文、反链、复习卡。

---

## 14. 需要拍板的决策

1. 是否接受被引用块写入隐藏 HTML 注释？
2. 第一版是否只做对照板，不做正文内嵌？
3. 卡片是否只读，编辑回源文档？
4. 是否允许同一源块创建多个视口？
5. 布局顺序是否只属于 board，不影响 Markdown 顺序？
6. 导出 board 时，是展开引用内容，还是只输出引用链接？

推荐答案：

```text
接受隐藏 ID
只做对照板
卡片只读
允许多个视口
board 顺序独立于 Markdown
导出默认展开内容 + 附来源
```
