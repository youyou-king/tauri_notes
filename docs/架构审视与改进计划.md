## 2. 目标架构

```text
Shell
├─ 核心命令 / 快捷键 / 设置 / 错误边界 / 健康状态
├─ 核心状态运行时
│    ├─ ThemeRuntime
│    ├─ WorkspaceRuntime
│    ├─ PanelLifecycle
│    └─ EditorSnapshot selectors
├─ PluginRegistry
│    ├─ manifest preflight
│    ├─ capability policy
│    ├─ dependency state
│    └─ contribution namespaces
└─ UI
     ├─ Dockview
     ├─ panels
     └─ plugin contributions
```

核心规则：

- Settings、通知、命令面板、错误边界属于 shell；
- 功能插件贡献内容和设置 section，不拥有 shell 入口；
- 业务状态只有一个写入口；
- 插件只能使用声明且被允许的能力；
- 迁移、备份、恢复必须可诊断。

## 4. 改进路线

### Phase 0：决策与护栏

目标：先把架构约束写成可验证规则，避免边改边漂移。

任务：

- [ ] 建立 `docs/adr/`；
- [ ] ADR-001：shell capabilities（设置、通知、命令面板、错误边界）；
- [ ] ADR-002：插件生命周期与 capability policy；
- [ ] ADR-003：状态所有权与 selector；
- [ ] ADR-004：持久化、迁移、备份；
- [ ] ADR-005：安全、安装模型、发布；
- [x] 增加架构 fitness tests：设置必须由核心入口提供、manager id 不能重新启用、插件不能直接写全局存储。

验收：

```text
ADR 可追溯
架构规则有自动测试
新增插件不需要修改 PluginProvider
```

### Phase 1：插件运行时治理

目标：插件失败不拖垮应用，插件贡献可诊断、可约束。

任务：

- [x] 插件管理器改为核心 settings section；
- [x] 增加核心 PluginHealth 视图；
- [x] `startSafely` 传播依赖失败，输出 `blockedBy`；
- [x] manifest preflight，非法插件进入 failures 而不是抛组合根；
- [x] 构建级 capability allowlist，默认拒绝未授权能力；
- [x] 插件注册表抽离为 `src/plugins/registry.ts`；
- [x] contribution ID 命名空间和冲突报告；
- [ ] 插件命令与核心命令冲突时显式记录。

验收：

```text
非法 manifest 应用仍能启动
依赖失败的插件不激活
未授权 capability 被拒绝
插件管理器不依赖任何功能插件
插件健康信息不进入插件管理器也能看到
```

### Phase 2：安全与桌面平台

目标：收紧攻击面，统一安装、文件和窗口边界。

任务：

- [x] 配置显式 CSP 并收窄 assetProtocol；
- [ ] `assetProtocol` 收窄到知识库和应用目录；
- [x] 评估并移除默认 `--no-sandbox`；
- [x] 统一安装模型为 currentUser + asInvoker；
- [ ] 使用正式 bundle identifier；
- [ ] 为 Tauri 命令引入结构化错误；
- [ ] 按窗口拆分 capabilities；
- [ ] 统一 OpenRequest（CLI / 单实例 / 拖放 / 文件关联）。

验收：

```text

asset 只能访问允许范围
关闭窗口、打开文件、文件关联路径有测试
安装器不需要管理员权限（若采用 perUser）
```

### Phase 3：状态与持久化

目标：消灭剩余的重复可写状态，建立统一迁移和恢复。

任务：

- [ ] 合并 ThemeProvider 与 appearanceRuntime 为 ThemeRuntime；
- [ ] EditorSnapshot 拆分为 selection / toolbar / stats selector；
- [x] 工作区选择改为原子命令 `select(mapId, node)`；
- [x] 面板状态：idle / dirty / saving / saved / error；Dockview 标签关闭已确认，程序化关闭仍待统一。

- [x] SQLite migration 每个版本使用事务；
- [ ] 迁移改用结构化 ledger，失败可重试；
- [ ] SessionSnapshot 保存 map、节点、面板、主题；
- [ ] 插件存储统一 `PluginStoragePort`，禁止直接使用 localStorage/IndexedDB；
- [x] 增加迁移前自动备份；恢复校验和回收站策略仍待实现。

## 6. Fitness Functions

建议加入自动检查：

```text
架构
  - 设置必须来自核心 toolbar / command
  - 插件管理器由 shell 提供，manager id 只用于兼容旧存储
  - 插件不能直接访问全局 localStorage / indexedDB
  - 插件注册表不依赖 PluginProvider

状态
  - selectedNode 必须属于 activeMap
  - EditorSnapshot 不重复保存 selectedBlock
  - 主题只有一个写入口

数据
  - 每个 migration 在事务中执行
  - 迁移失败可重试
  - 会话恢复包含 map / node / panel

发布
  - 版本号一致
  - release 资产有 checksum
  - 三平台 bundle 至少构建一次
```

## 7. 非目标

本计划明确不做：

- 重写插件内核；
- 引入运行时第三方 JS/Rust 插件；
- 把所有 UI 临时状态放进全局 store；
- 为每个源码目录增加 README；
- 在没有迁移和恢复设计前引入复杂跨设备同步。

---

## 8. 执行规则

每个任务必须满足：

1. 有明确的状态归属；
2. 有失败路径测试；
3. 不引入新的可写副本；
4. 文档和测试同步更新；
5. 不破坏现有 `.note` 格式；
6. 不把安装包提交到 Git。

发布前：

```text
npm run verify:all
git tag vX.Y.Z
GitHub Release
```

## 9. 下一步建议

第一刀建议从 **Phase 1 的插件运行时** 开始，而不是先改 UI：

```text
1. 核心插件管理器 / PluginHealth
```
