## 1. 重构目标

### 1.1 必须解决的问题

- `App.tsx` 同时承担状态、业务流程、面板编排和持久化；
- 面板组件直接依赖 `DockWorkspace` 内部上下文，复用困难；
- 颜色、边框、阴影散落在 `styles.css`、TSX、ReactFlow 节点内联样式中；
- Tauri 命令散落在组件内，UI 与 IPC 强耦合；
- 缺乏统一的 Panel 外壳、命令、快捷键和菜单模型；
- 主题只能靠追加 CSS 变量，无法形成可扩展主题系统。

### 1.2 验收标准

- 新增面板不需要修改 `App.tsx` 和 DockWorkspace 主流程；
- 新增主题不需要改组件代码；
- 组件样式不出现裸十六进制颜色；
- UI 组件不直接 `invoke`；
- 主题切换不改变布局、数据、面板状态；
- 核心流程有单元测试/E2E 验证；
- 重构期间每个阶段都能 `npm run build` 和 `cargo test`。

## 2. 目标分层

```text
presentation（React 组件、面板、主题）
        ↓
application（用例编排、Store、Controller）
        ↓
domain（模型、规则、ID、事件）
        ↑
infrastructure（Tauri IPC、SQLite、文件、日志）
```

依赖方向：

```text
features → application → domain
features → ui
ui → design-system
infrastructure → domain/application
app → 所有层（仅组合）
```

禁止：

- `domain` 引入 React/Tauri；
- `ui` 直接调用 Tauri；
- `application` 引入 Dockview/ReactFlow；
- 组件互相 import 内部实现。

## 5. 核心契约

### 5.1 IPC Client

```ts
export interface WorkspaceApi {
  open(path: string): Promise<WorkspaceView>;
  openNote(path: string): Promise<WorkspaceView>;
  create(path: string, title: string): Promise<WorkspaceView>;
  save(path: string): Promise<void>;
  backup(workspace: string): Promise<string>;
}

export interface DocumentApi {
  load(workspace: string, documentId: string): Promise<DocumentBlocks>;
  save(input: SaveDocumentInput): Promise<void>;
  rename(workspace: string, documentId: string, title: string): Promise<void>;
}
```

组件只能依赖 `application` 暴露的 service，不直接依赖 `invoke`。

### 5.2 Panel 注册表

```ts
export type PanelDefinition<TParams = unknown> = {
  id: string;
  component: ComponentType<PanelProps<TParams>>;
  icon: string;
  singleton?: boolean;
  title: (params: TParams) => string;
};
```

`DockWorkspace` 只负责 panel 生命周期和布局；panel 自身不再直接操作 Dockview API。

### 5.3 Command 注册表

```ts
export type CommandDefinition = {
  id: string;
  label: string;
  shortcut?: string;
  enabled?: (ctx: CommandContext) => boolean;
  run: (ctx: CommandContext) => void | Promise<void>;
};
```

导航栏、工具栏、右键菜单、快捷键统一查表。

## 6. 设计系统与主题

### 6.1 Token 三层

```text
primitive → semantic → component
```

组件只能消费 semantic/component token，禁止裸色值。

### 6.2 主题文件

```json
{
  "schema": 1,
  "id": "ocean",
  "name": "Ocean",
  "base": "dark",
  "tokens": {
    "color.bg.app": "#0b1020",
    "color.accent": "#58a6ff",
    "radius.panel": "8px"
  }
}
```

主题目录：

```text
%APPDATA%\com.example.tauri-notes\themes\
```

### 6.3 CSS 分层

```css
@layer theme, tokens, base, components, layout, critical;
```

- 用户主题只进入 `theme` 层；
- 布局/交互位于 `layout`、`critical`；
- 主题禁止 `!important`、布局属性和全局选择器；
- 组件通过 `data-part` / `data-state` 暴露稳定的主题接口。

### 6.4 自定义主题

- 只允许 token + recipe；
- 高级模式允许受控 CSS，但限制属性和选择器；
- 禁止脚本、远程资源、字体外链；
- 损坏主题自动回退 `builtin:dark`；
- 提供“恢复默认主题”。

## 7. 状态管理

按领域拆分 store：

```text
workspace-store
panel-store
document-store
map-store
theme-store
search-store
board-store
```

规则：

- store 不 import 组件；
- store 只通过 service 访问 infra；
- 跨 store 通过事件/selector；
- localStorage 只保存 theme、session、layout、recent，不保存文档内容。

## 8. 会话与持久化

会话格式：

```json
{
  "version": 1,
  "roots": ["C:/a.note", "D:/b.note"],
  "activeRoot": "D:/b.note"
}
```

行为：

- 直接启动：恢复 roots + Dockview layout；
- 带 `.note` 参数：只打开该文件，重置布局；
- 恢复失败：默认布局 + 示例库。

### 导图实时渲染与拖拽（2026-10-29）

- 根因：拖拽过程中 `onNodeDrag` 每帧写回 `map`，触发 `buildMindMap` 重排，React Flow 内部位置与受控布局互相覆盖。
- 现在拆成两层状态：
  - 布局层：`buildMindMap` 只生成一次性位置提示；
  - 交互层：React Flow 通过 `useNodesState` 拥有实时节点位置。
- `useMindMapFlow` 负责调和：
  - 已有节点保留实时位置；
  - 新节点使用布局位置；
  - 标题、文档标记、选中样式从布局数据更新，但不覆盖拖拽位置。
- 拖拽期间不再写 `map` 或后端；`onNodeDragStop` 才提交位置并持久化。
- 布局同步只发生在结构、标题、选中状态变化时，不会每帧重排。
- 手动位置判断改为 `x !== 0 || y !== 0`，支持 `y = 0` 的横向手动布局。
- 新增单测：实时位置保留、新节点布局、横向手动位置。
- 验证：前端 116、Rust 32、E2E 28。
